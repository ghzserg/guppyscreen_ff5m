# Navigation Bar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A 60 px navigation bar (tabs + Stop) on every screen; all other screens live in a 740×480 content area; no Back buttons; a Print tab that shows the file list when idle and the print status while printing.

**Architecture:** A singleton `Nav` (`src/nav.{h,cpp}`) owns two objects on `lv_scr_act()`: the bar (x 0..59) and the content area (x 60..799). Tab roots, sub-screens and dialogs are children of the content area; the panels keep opening themselves with `lv_obj_move_foreground`. "Open" means *above the topmost tab root* in the content area's z-order, so the nav needs no help from panels to know what to close. `lv_tabview` goes away.

**Tech Stack:** C++17, LVGL 8, doctest integration tests in `tests/` (real app, fake Moonraker).

**Spec:** `docs/superpowers/specs/2026-11-15-nav-bar-design.md`

## Global Constraints

- Bar width 60 px, content area `hor_res - 60` × `ver_res` (740×480 on the AD5M).
- Tab order top to bottom: Home, Print, Tune, Settings; Stop at the bottom. Five slots of 96 px (480 / 5, today's tab height). The Print button exists from Task 3; until then its slot is empty.
- Macros and Console are not tabs: two buttons in a new third row of the Settings grid (rows `2:5:5` → `2:5:5:5`; ids `macros` col 0, `console` col 1, row 3, `LV_GRID_ALIGN_CENTER`/`START` like the other Settings items) open them as Settings sub-screens. Labels `_("Macros")`, `_("Console")`; icons: `code_img` for Console, an existing `assets/material` image for Macros (builder's pick, no new assets).
- Tab glyphs and font as today (`main_panel.cpp:19-23`, `materialdesign_font_40`); active tab grey (`lv_palette_main(LV_PALETTE_GREY)`), others the bar's background; no outline/border.
- Stop: the `emergency` image (64×64, already red) zoomed to 48 px (`lv_img_set_zoom(img, 192)`), bar background, no label; confirmation msgbox when `/prompt_emergency_stop` is true, text `_("Do you want to emergency stop?")`.
- Print tab icon: the `print` image (white) zoomed to 40 px (`zoom 160`).
- Panels compiled only without `GUPPY_FF5M` (wifi, TMC, power, printer select, print_panel's `prompt_cont`) are not touched.
- Project rules: one process per test case, no commas in test names, smoke test before refactoring a path, `GUPPY_FF5M` guards kept. Run tests with `make test` (from repo root); subsets with `make test TEST='*name*'`.
- Commit at the end of each task, message ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A screen opened by code while a dialog is open (Klipper prompt button → Extruder; print start → Print tab): the dialog must stay on top and answerable.
2. Disconnect and reconnect mid-print: the init panel covers everything; afterwards the Print tab shows the print status and is active; after reconnect when idle, its root is the file list and nothing is activated.
3. Two stacked sub-screens (Extruder → Spoolman) closed by one tab tap: both closed, both leave actions run once.
4. The Print tab's root switches (print completes) while it is active with Fine Tune open over the print status: Fine Tune closed, file list shown, Print still active.
5. Sub-screens whose old constructor-time `lv_obj_move_background` was missing (Homing, Fans, LED were hidden only by the tabview created after them): must start closed.

Tests for 1–5 are in Tasks 2–4.

**Interfaces:**
- Produces (`src/nav.h`):
```cpp
class Nav {
 public:
  enum Tab { HOME, PRINT, TUNE, SETTINGS, TAB_COUNT };
  static Nav &get();          // first call creates bar + content on lv_scr_act()
  lv_obj_t *bar();
  lv_obj_t *content();        // parent of tab roots, sub-screens, dialogs
  lv_obj_t *add_tab(Tab t, const char *glyph);            // new root: 100%x100%, pad 0, not scrollable
  void add_tab(Tab t, lv_obj_t *root, const lv_img_dsc_t *icon);  // existing root (Print)
  void set_root(Tab t, lv_obj_t *root);  // swap a tab's root; if t is active, as activate(t) on the new root
  lv_obj_t *root(Tab t) const;
  void activate(Tab t);
  Tab active() const;
  void on_leave(lv_obj_t *screen, std::function<void()> action);
  void add_dialog(lv_obj_t *dialog);
  bool dialog_open() const;
  void set_stop(std::function<void()> stop);
  lv_obj_t *tab_button(Tab t);
  lv_obj_t *stop_button();
  void start();               // after all panels exist: closes every non-root child, activate(HOME)
};
```
- `activate(t)`: remember open dialogs (registered dialogs above the topmost root, in z-order); for every other child above the topmost root, top first: run its `on_leave` action if any, then `lv_obj_move_background`; `lv_obj_move_foreground(root)`; re-raise the remembered dialogs in order; update the highlight. If `t` differs from the active tab, the old tab root's `on_leave` action runs first (roots can have one too: the file list).
- A tap on a tab button calls `activate(t)` unless `dialog_open()`. The Stop button works always.
- `ButtonContainer::confirm(const std::string &text, std::function<void()> on_ok)` (static): today's `handle_prompt` msgbox; `handle_prompt()` calls it.
- `tests/harness/ui.h`: `bool is_shown(lv_obj_t *obj);` (the existing static `shown`, under the lock) and `void tap_tab(Nav::Tab t);` (taps `Nav::get().tab_button(t)`, then `app::pump(100)`).

### Task 3: Print tab

**Files:**

**Interfaces:**
- Consumes: `Nav::add_tab(PRINT, files_cont, &print)`, `set_root`, `root`, `activate`, `on_leave`.
- `files_cont` (file list) is the PRINT root at start; `status_cont` is created in `content()` and becomes the root while printing/paused. The file list's leave action (`file_panel.uncache_thumbnail()`) is now the root's, run when leaving the Print tab. Remove from the print status `back_btn` and `emergency_btn` (items `back`, `emergency`); remove the file list's `status_btn` (item `status`).
- State rules (spec "Print tab"):
  - `print_stats.state` `printing`/`paused` → `set_root(PRINT, status_cont)`; anything else → `set_root(PRINT, files_cont)` (+ today's `reset()`, mini status hide).
  - Non-empty new `print_stats.filename` → `set_root(PRINT, status_cont)` + `activate(PRINT)`. Empty filename → nothing.
  - `init()` while printing/paused (connect/reconnect) → status root + `activate(PRINT)`.
  - Pause/resume → no activation.
  - Cancel button: only sends `printer.print.cancel` (no `background()`, no `reset()`).
  - Home's Print button is removed (main item `print`); mini status tap → `activate(PRINT)`; print status temperature/fan buttons → `activate(HOME)`; the file list's "already printing" branch → `activate(PRINT)`; after `printer.print.start` the file list no longer calls `foreground()` (the filename notification switches and activates).
- Thumbnail container and filename label width: 35% of `lv_obj_get_content_width(Nav::get().content())` (call `lv_obj_update_layout` first) instead of the physical display width.
